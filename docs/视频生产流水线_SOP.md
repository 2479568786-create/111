# 视频生产流水线 · 固定合作机制（SOP 定稿 v2）

> 适用范围：本群「YouTube项目工作群」所有 YouTube 视频生产
> 频道定位：双频道并行——A「时事/社会现状」（素材拼接，旧号）＋ B「普通人手搓 AI 电商」（录屏为主、剪映配音，新号）
> 版本：v2.2 · 2026-10-21 · 分工调整（找素材写稿 / 编剧编排分镜）+ 剪映配音交付

## 一、成员分工

| 角色 | 成员 | 职责 |
|---|---|---|
| 总协调 + 选题立项 | Youtube选题（群管理员） | 立项、盯进度、最终验收 |
| 编排 + 分镜 | 编剧 | 编排进度 + 视频安排：选题卡、排期、分镜表、切点表、画面语义（不写稿） |
| 写稿 | 找素材 | 逐字稿 + 纯口播 + 事实核查表（口播只放能念的字、数字汉字、一句一断） |
| 剪映交付包 | 视频制作 | 收稿 + 分镜 + 录屏 → 无声画面 + 字幕 + 分镜表 + 口播 |
| 质检兜底 | Chief | A10 口播↔分镜一致 + A/B/C + 事实口径，兜底协调 |

## 二、固定流程（5 步串行）

1. **选题**：用户口述 → 编剧转成选题卡（讲什么 / 为什么 / 不碰什么）
2. **写稿**（找素材）→ 逐字稿.md + 纯口播.txt + 事实核查表.csv
3. **编排 / 分镜**（编剧）→ 分镜表.csv（一句一行）+ 切点表 + 画面安排
4. **剪映交付包**（视频制作）→ 无声画面 + 字幕.srt + 分镜表 + 口播（先跑 channelB/check_shot_table.py PASS）
5. **质检**（Chief）+ **验收**（Youtube选题）→ 交付用户

**规则：上一步交付完整，下一步才开工。每一步交付后，由管理员 @下一步 成员。**

### 2.1 四条跨环节硬规则

1. **报数一致**：任何交付说明里的数字（CER、时长、字数、行数）必须与随附日志/文件一致；报「行数」注明含不含表头。不一致按交付不完整退回。
2. **改稿联动**：口播一改 → md+txt 同步 + 重跑自检 + 版本号 +1 → **该段及之后的配音与 SRT 必须重出**；SRT 必须由**最终配音时间轴**生成，不许手改时间码凑。
3. **机检可复现**：任何「放行」必须附一条可复现的机检命令 + 输出；只说「我检过了」不算。
4. **块号不跨环节通用**：各环节各切各的块，编号只在环节内有效；跨环节定位一律用「时间码区间 + 块首句」，逐块日志必须用 1 基块号 + 带起止秒。

### 2.2 停止 / 暂停指令的语义

群里说「停」时，必须区分两种意思，由发指令的人写清楚：

- **停新任务**（默认）：不再启动新的阶段/新片；**已跑完或在收尾的产物照常交付留存**，不浪费算力，也不算「抗命」。例：管理员说暂停配音重出，视频制作手上已跑完的 v5 正常交付。
- **立即中止**（要明说「立即中止」）：连进行中的渲染/生成也放弃，产物丢弃。只在产物会污染下游或占用必需资源时使用。

配套两条：① 收到「停新任务」的成员交付时注明「此产物完成于停止指令之前/之后」；② 停止不影响已交付物的版本号与改稿记录，恢复时从记录里的参数续（如「重出范围 0:41–1:55」），不凭记忆重来。

## 五、各环节接口契约

### 5.1 编剧

- **输入**：管理员按 9 字段选题卡下 brief——选题简称、中心思想、创新主轴、时长档、档位、语言、禁区、参考、**delivery promise**（本片一句可验证承诺，如「非幻灯片、每镜含动态」）。缺项按默认走（热档 6–7 分钟、中文、可点名有公开处罚记录的企业、不点名未受处罚企业），并在交付卡注明。
- **输出**：五个同前缀文件 + 群内交付卡——`…_逐字稿_<时长>min.md`、`…_纯口播.txt`、`…_事实核查表.csv`、`…_纯口播_TTS分块.csv`、`…_scene_plan.json`（机读分镜，`python scripts/分镜导出.py` 生成）。交付卡写路径 + 字数（两种口径）+ 已核数字 + 风险项 + 下游注意。delivery promise 写进 md 头部 + json + 交付卡三处一致。
- **硬规则**：
  - 纯口播里只放能念出来的字——无段号、无时间码、无括注；
  - 数字全用汉字（一百八十二点二八亿、百分之四、二〇二〇年）；
  - 段间空行、段序与 md 完全一致；问号保留（决定配音语调）；
  - **文言、生僻专名、人名不进音频**，改白话转述或改称谓，原文/专名转花字上屏（TTS 最易退化处）。
- **字数/时长口径（统一，不许各报各的）**：
  - 一律写「N 汉字 + M 个「〇」= N+M 念读字」；
  - 实测 **215–220 念读字/分**（含句间停顿），6–7 分钟 = **1300–1500 念读字**；250 字/分只作粗估、不进交付卡。
- **改稿联动**：见 2.1 第 2 条；改稿记录按版本逐行写进 md 末尾，不许只写在群消息里。
- **自检**：`python scripts/脚本自检.py <纯口播.txt> [目标分钟]` + `python scripts/稿本同步检查.py`（md↔txt 必须 ALL SYNC）。
- 详见 `编剧交付规范_v2.md`。

### 5.2 找素材

- **输入**：读 `_scene_plan.json` 的 `broll_slots[].id`（每个槽对应一个素材，不再解析 md）+ 逐字稿（含优先级和红线）；有配音 SRT 时用 SRT 对齐时长。
- **输出**：`素材包/` 目录——素材需求表、剪辑摆放方案、候选清单、时长覆盖台账、按段号归好的 assets 文件夹。只做方案和摆放，不实际剪时间线。
- **版权审核已停用（2026-10-20 用户决定）**：不再核实授权、不标红线、不判白名单、不卡收费素材；素材来源由用户自行对 YouTube 的版权规则负责。台账只记「段号/文件名/使用时长」用于组装。
- **坑**：Wikimedia 对共享出口 IP 限流 429，越重试越久，要冷却或换源。

### 5.3 视频制作

- **输入契约（三条硬约束）**：
  - a) 素材必须在工作区内，给文件夹路径——Bots 读不到桌面/OneDrive，没拷进来就报缺，不自造；
  - b) 脚本给「`_scene_plan.json`（机读分镜）+ 纯口播.txt」两份，按 `scenes[].start_s/end_s` 排时间线；
  - c) 给的是已有画面版（烧死字幕那种）只能整体对齐、不能逐段锚定；要逐段就配分镜表或可编辑工程。
- **配音线路（定死）**：默认走 `tts-lab`（MOSS-TTS-Nano，纯 CPU，参考音 `ref_12s.wav` = 「杰哥说」音色，不崩）。Voicebox「杰哥说」克隆线要 15GB+ 内存、本机会崩，**只在必须用克隆音色时才碰**。
- **配音质量硬标准（「吐字不清」解法）**：
  - 按句切成 12–15 秒小块，每块生成后立刻 ASR 回读验收；
  - CER 超档、有重复串、或电平塌陷 → 换种子重生成，最多 5 次；
  - 块内响度统一归一 + 首尾淡入淡出；
  - **不用 atempo 变速**，时长差额按句读分配到停顿里；
  - 文言/人名块要人耳确认并有花字兜底；专名不进块首。
- **时间预算**：整条配音 7 分钟 → 停顿收窄 + 响度 + 封装 1 分钟 → 渲染 443 秒片约 4.5 分钟 → look 全片检查 1–2 分钟；画面复用版式 1–2 小时，新片式另算。
- **质检切分**：视频制作自查技术项（look 确定性/黑帧/黑边/文字裁切/响度）并在交付说明里报；**Chief 用 `scripts/质检机检.py` 对技术项做全量机检复核，但不再人工逐帧看**（机器复核 ≠ 人工重复）。
- **画面 / Studio 产线**：OpenFilm 需设环境变量（`OPENFILM_HOME`、`OPENFILM_LIBRARY`、`PLAYWRIGHT_BROWSERS_PATH`）；用 `npx.cmd -y openfilm@latest open .` 重启 Studio（PowerShell 用 npx.cmd，不用 npx.ps1）；`look` 校验、`render` 出片、一镜一页、`frame(t)` 不留跨帧状态。
- **产线脚本**：`scripts/tts_chunks.py`、`asr_gate.py`、`pick_multi.py`、`assemble_voice.py`、`srt_from_timeline.py`、`finalize.py`、`chunk_log.py` 等，命令原文与参数详见 `视频制作_产线规范_v1.md`。

### 5.4 Chief 质检

- **放行规则**：四道闸门串行，**前一道不过不看下一道**；**阻断项必须清零才放行**；**一次只退给一个人**（文风/事实/口播→编剧，素材/版权→找素材，配音/字幕/成片→视频制作，选题方向→管理员）。
- **结论卡固定格式**（群内一条）：
  ```
  质检结论：放行 / 退回（阻断 N 项）
  - 阻断（N）：编号 问题（位置）
  - 建议（N）：…
  - 退回给：谁
  - 证据：质检报告_<片名>.md
  ```
- **四道闸门与判据**（机检项全部由 `scripts/质检机检.py` 出数，不手判）：
  - **A 脚本**：A1 字数时长（220 字/分 ±10%）/ A2 感叹号 0 / A3 无 40 字以上长句 / A4 无阿拉伯数字 / A5 段间空行且段序与 md 一致；A6–A8（钩子、文风、标题标签）人判。
  - **B 字幕一致性**：B1 SRT 与纯口播逐字一致 / B2 单行 ≤18 字、每屏 ≤2 行 / B3 时间码单调、无重叠、不越界 / B4 单条 2–8 字/秒 / B5 相邻字幕无 >3s 空洞。
  - **C 成片**：C1 1920×1080 ≥24fps h264 / C2 成片时长 ≈ 字幕末条（片尾余量 −5s~+0.5s）/ C2b 记录实际字/分 / C3 有音轨且不短于画面 / C7 坏块（逐 100ms 瞬时响度低于有声基线 18 LU 且 <−30 LUFS，持续 ≥1.2s）/ C8 响度（−14 LUFS ±1.5 / LRA ≤12 LU / 真峰值 ≤−1.5 dBFS）；C4–C6（音画同步抽听、首尾、工程可交付）人判。
  - **D 事实口径**（版权审核已停用，2026-10-20 用户决定）：D4 事实核查表有「依据」列、数字标口径、存疑标「有争议」；D3/D5/D6（争议标注、点名边界）人判。**素材来源/授权/白名单/红线一律不再判定。**
- **ASR/CER（配音质量）**：分块日志必交 `块号, 文本类型, 起止秒, CER, 重试次数, 判定`（另附 ASR 回读 + 原稿）；一律按正文 ≤25% 判，文言/人名块属禁止项，仅管理员特批例外时按 ≤30% 判且必须人耳确认 + 花字兜底；有重复串即退。**报数与日志不一致，按交付不完整处理。**
- **一条命令**：`python scripts/质检机检.py --mp4 成片.mp4 --srt 字幕.srt --txt 纯口播.txt --facts 事实核查表.csv --target-min <目标分钟>`（6–7 分钟片填 7）。
- **存档**：每片放行同时留 `质检报告_<片名>.md`（机检原始输出 + 人判项 + 结论卡）与逐块 ASR 日志。

## 八、机制升级（借鉴 OpenMontage，v2.1 已采纳）

### 8.1 签收门 + 项目状态.json（治「说了停还在跑」）

- 每支片一个 `项目状态.json`，逐环节记录状态：`pending / awaiting_human / completed`。
- 环节标 `completed` 必须带「签收人 + 签收时间」字段；**没签收不许标 completed**（写入器拒绝无签收的 completed）。
- 一次授权只盖一个闸门；「停新任务 vs 立即中止」语义见 2.2。
- **签收字段只能由签收人本人填写**（或管理员代签并注明「代签」）；被签收方不得替对方写 `signed_by`。
- 状态.json 由各环节交付时写入，Chief 机检校验字段齐全、签收完整。
- script 段字段名：`delivered`（版本）、`version`、`validator`、`scene_plan`（指向 scene_plan.json 路径）；其余环节字段由 Chief 定 schema。

### 8.2 机读契约（分镜表 / 素材表 schema）

- 编剧交付「分镜表」须含机读版（固定字段：镜号 / 时长 / 画面 / 台词 / 花字 / 可视化 / 素材 slot），不止 md。
- 找素材台账在七列基础上补「归属段号 + slot 描述（名词+形容词的具体画面）」。
- 下游（找素材 / 视频制作 / Chief 机检）直接读机读表，不人肉解析 md。
- **分镜表粒度（定）**：`_scene_plan.json` 是编剧唯一权威交付契约（镜 = 素材 slot 单位）；视频制作的渲染 json（镜 = 渲染单位）从它派生，加 `parent_scene` 映射，**不许两边各维护一份分镜表**。

### 8.3 空镜 CLIP 语义索引（找素材环）

- 管线：中文分镜描述 → 翻译成「名词+形容词」英文视觉短语（不写情绪/意图词）→ CLIP 检索 top-k → 人工确认。
- 脚本 `clip_index.py`、索引 `clip_index.npz`（每帧 512 维，建一次可复用）。
- 局限：英文 CLIP 对中文语境概念（国风水墨 / 古画书影）弱，此类素材靠文件名标签 + 人工确认。

### 8.4 渲染前预检 + delivery promise（防 PPT 化）

- 编剧立项时写一句可验证的 `delivery promise`（如「本片每镜含动态，非幻灯片」）。
- 视频制作渲染前跑预检清单（时长 / 字数口径 / 字幕条数 / 花字时间轴 / 素材覆盖 / 镜数与平均镜长 / 渲染规格），promise 被违反即 block 不渲染。
- Chief 机检加 **C10**（黑帧、静态画面占比、镜头时长分布），对着 promise 验。

## 附：已实测的关键参数

- 语速 **215–220 念读字/分**（1591 念读字 → 443.43s ≈ 215 字/分，v1.3 实测；1587 为旧稿字数）；6–7 分钟 = 1300–1500 字。
- 响度 **−14 LUFS / LRA ≤12 LU / 真峰值 ≤−1.5 dBFS**。
- ASR 基线 CER ≈ **13.7%–15.7%**（同模型同参考音对干净语音的误判率，不是配音缺陷）。
- 机检实效：v3 抓到 B1/B3 阻断；听诊报告定位 3 处坏块（71.7s 起、最长 4.6s@91.0s）；v4/v5 放行（0 阻断），并从逐块日志查出「最高 CER 20.0%」与实际 28.21%/26.32%/25.64% 不符——报数必须与日志一致。
