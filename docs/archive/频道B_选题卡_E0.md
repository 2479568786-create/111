# 频道 B · 选题卡（模板 + E0 实例）

> 用途：Chief 质检要拿「选题卡 → 稿子」对照判有没有跑题，也留作以后回溯「这期当时为什么这么做」。
> 用户口述选题后，由编剧（编排）转成这张卡，2 分钟内完成；没有卡不开工。
> 日期：2026-10-21

## 模板（每期必填 5 个最小字段）

1. **这期讲什么**（一句）
2. **为什么做这期**（一句，能说服自己）
3. **观众拿走什么**（铁律：今晚能做什么他昨天做不了的事，必须是具体动作）
4. **不碰什么**（禁区：不点名、不编数、不吹、不卖什么）
5. **时长与结构**（分钟 / 念读字 / 段落骨架）

## E0 实例：为什么做这个频道

| 字段 | 内容 |
|---|---|
| 集号 / 选题简称 | E0_为什么做这个频道 |
| 1 这期讲什么 | 一个在圣彼得堡的普通学生，为什么自己搭一套电商工具，以及这个频道准备给你什么 |
| 2 为什么做这期 | 新号第一条不是卖工具，是先把「凭什么信我」讲清楚：真店、真订单、真代码，三样都可核 |
| 3 观众拿走什么（铁律） | **今晚花 20 分钟，算清一张商品图的真实成本**：注册中转站充最小额度 → 跑一张图 → 把失败重试算进去 → 把结果写在纸上 |
| 4 不碰什么 | 不点名未受处罚企业；不编任何数字（ERP 报价、会员费、成本等未核一律不写）；不吹 AI；第一季不卖课；不做宏观趋势判断 |
| 5 时长与结构 | 7–8 分钟 / 1500–1750 念读字（实测口径见下）；骨架：痛 → 我是谁 → 为什么做 → 三个承诺 → 今晚拿走 → 钩子 |
| 6 字数与语速口径 | 当前稿 1566 念读字（含拉丁词按 1 单位）；剪映朗读按 215–220 念读字/分，成片约 7.1–7.3 分钟 |
| 7 画面三源 | Ozon 后台 / VS Code + Codex 跑代码 / GitHub 仓库，轮切（单源 ≤20 秒），关键帧放大 1.8–2 倍 |
| 8 素材依赖（用户提供） | Ozon 后台（首页/订单/详情）、VS Code 报错画面、GitHub 仓库与 README、中转站控制台与生图记录、Ozon 类目页；规格见 `频道B素材\_收料说明.md` |
| 9 事实依赖（待补） | ①ERP 报价金额 ②会员费金额 ③最近一次报错原文 ④开店时间 ⑤第一单日期 —— 补完升 v1.0；关键词搜索量数据标「用户提供·未核」，不进片 |
| 10 交付接口 | 写稿方：`E0_纯口播.txt`（一句一行）；编排方：`E0_分镜表.csv` + `E0_为什么做这个频道_scene_plan.json` + 逐句卡点表；视频制作：剪映交付包 6 件 |

## 写稿方看的规则（交接）

写稿规范不另立文件，直接用这两份：
1. `频道B_收稿检查单_v1.md` **A 节 12 条**（字数 / 一句一行 / 数字汉字 / 编号不断句 / 型号拆写 / 名词串拆开 / 英文词按读法表 / 禁读项 / 句长 / 事实出处 / 铁律 / 顶部元信息）；
2. `频道B_参考音台词与读法表_v1.md` **第四节四条改词规则** + 英文词读法对照。

工具共用（工作区）：`脚本自检.py`、`稿本同步检查.py`、`分镜校验.py`、`tts_chunks.py`。
一次改稿规则不变：改一句，重跑前两个脚本，再把分镜表交给编排方重出——两边断句必须一致，否则字幕整段错位（视频制作的 `check_shot_table.py` 会在出包前拦）。
