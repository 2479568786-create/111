> v2 相对 v1 的增量：① 字数报数口径统一；② 新增第 4 个交付文件（TTS 分块表）；③ 文言与专名禁入音频（v1.3 教训）；④ 同音误读处理规则；⑤ 块号引用规范；⑥ 花字时机写进分镜表。

## 一、我的输入：选题卡（8 个字段）

管理员立项时按这张卡下 brief，缺项我按默认值走并在交付卡里注明。

| 字段 | 说明 | 缺失时默认 |
|---|---|---|
| 1. 选题简称 | 用于文件名，如「董仲舒_增量存量」 | 必填，缺则退回 |
| 2. 中心思想 | 一句话，必须能反驳一个直觉答案 | 必填 |
| 3. 二次创新方向 / 主轴 | 这一版和原稿最大的不同，一两句话 | 沿用原稿主轴 |
| 4. 时长档 | 目标时长 + 念读字数区间 | 6–7 分钟 / 1300–1500 念读字 |
| 5. 档位 | 冷叙事 / 热档硬核；冷峻度、口语度 | 热档 6–7 分钟 |
| 6. 语言 | 中文 / 英文 / 俄文 | 中文 |
| 7. 禁区 | 不能碰的人、事、词；是否允许点名有公开处罚记录的企业 | 可点名公开处罚记录企业；不点名未受处罚企业；不做群体定性 |
| 8. 参考 / 截止 | 对标频道或视频链接；优先级 | 无参考，按正常排期 |

## 二、我的输出：5 个文件 + 1 张交付卡

1. `<选题简称>_逐字稿_<目标时长>min.md`（主文件）
   - 标题备选 3–5 个（含 A/B 思路与封面建议）
   - 15 秒钩子（口播 + 画面 + 字幕）
   - 逐段逐字稿：段号 `S01..Sn` + 时间码 `M:SS–M:SS` + 四件套（口播 / 画面 B-roll / 字幕 / 节奏）
   - **花字行**：凡不念出声、只上屏的原文 / 数字 / 人名 / 出处，全写在这行
   - **分镜表**：凡花字有起停时机的段落，必须用表格把「口播块号 + 口播内容 + 画面/花字 + 时间硬约束」写死（v1.3 新增，见第六节）
   - 素材清单表：优先级、对应段号、画面说明（**版权审核已按用户要求停用，2026-10-20**：不列版权/红线字段，只描述画面需求）
   - CTA、简介、标签
   - 事实核查与口径表
   - 设计理由、可选变体、自检数据、改稿记录
2. `<选题简称>_纯口播.txt`（下游源文件，给配音、SRT、时间线）
3. `<选题简称>_事实核查表.csv`（给 Chief 质检；与 md 同源，可机读）
4. `<选题简称>_纯口播_TTS分块.csv`（给配音；`python scripts/tts_chunks.py <纯口播.txt> [读速]` 生成，见第五节）
5. `<选题简称>_scene_plan.json`（机读分镜契约 scene_plan/v1；`python scripts/分镜导出.py` 生成、`python scripts/分镜校验.py` 14 项 PASS 才算交付，见 `分镜契约_v2.md`）
6. 群内交付卡（一条消息）：路径 + 字数（两种口径都写）+ 校验结果（脚本自检 / 稿本同步 / 分镜校验三项 PASS）+ 已核数字 + 风险项 + 下游注意 1–2 条 + 重出范围

**命名规则**：所有文件同一前缀，前缀 = 选题卡第 1 字段，不另起别名。

**工具**：`scripts/脚本自检.py`（文风/字数）、`scripts/tts_chunks.py`（分块表）、`scripts/稿本同步检查.py`（md↔txt 逐行比对）。

## 三、纯口播 txt 的四条硬规则（被下游直接使用，不能有例外）

1. **只放能念出来的字**：段号、时间码、括号注释、画面提示、「P.S.」全部不进。
2. **数字全用汉字读法**：金额——一百八十二点二八亿；百分比——百分之四；年份——二〇二〇年；数量——一百六十三万家。阿拉伯数字一律不出现（避免 TTS 读错）。
3. **段与段之间空一行**，一段一个信息、2–6 句；段序与 md 完全一致，不合并、不拆分。
4. **标点保留问号**（决定配音语调），句号照常；引文保留引号；括号内的口径说明只留在 md。

**v2 新增，第 5 条**：**文言、生僻专名、人名不进音频**。文言引文（「受大者，不得取小」）、书名（《汉书》）、生僻人名（公仪休）一律改白话转述或改称谓（「这个人是鲁国的国相」），原文与专名转花字上屏。原因见第六节。

---

## 四、字数与时长口径（v2 统一，不许再各报各的）

- **报数一律写两种口径**：`N 汉字 + M 个「〇」= N+M 念读字`。`scripts/脚本自检.py` 只统计汉字，会把「〇」漏掉（全片 7 个「〇」就是 7 字差），所以必须补一句。
- **时长两档，交付卡写实测那档**：
  - 粗估 250 字/分：只用于写稿时心里有个数，**不进交付卡**；
  - 实测 **215–220 念读字/分**（含句间停顿，由成片反推）：v4 成片 443.433 秒 / 1593 念读字 = **215.6 字/分**，这是本机「杰哥说」这条线的真实值。
- **两档差 15–17%，必须说清楚**：董仲舒这条 1591 念读字，粗估 6:22、实测 7:23——片长实际是 7:23，不是 6 分多。以后新稿一律按 **1300–1500 念读字 = 6–7 分钟** 定字数，粗估值只写在自检表里并标明「粗估」。
- v1.3 这条片子定在 1591 念读字（7:23）已超 6–7 分钟窗口，因画面已按 443.433 秒做定，**本片不回改**；下一条起按 1300–1500 执行。

## 五、TTS 分块表（v2 新增，第 4 个交付文件）

`python scripts/tts_chunks.py <纯口播.txt> [读速=218]` 生成，规则：

1. 只在**整句行边界**切，绝不切句子中间；
2. 不跨段（不跨空行分隔的段落），段序与 md 一致；
3. 目标 44–56 有效字（≈12–15 秒），尾部过短块不硬并（合并上限 58 字）；
4. **`FORCE_BREAK` 强制断块**：需要留空拍 / 上花字的整句必须收在块尾（v1.2 的「他把这层意思，压成了六个字。」就写在这里）；
5. 输出列：`分块ID, 段, 有效字数, 预计秒数, 文本`，块 ID 形如 `S03-C04`。

**用途**：配音按块生成、按块 ASR 验收。我的表按句子切，视频制作按 token 切，**两边块号不通用**——所以下游一律用「时间码区间 + 该块首句」定位，不许只用块号互指（v4 那个「c002 看起来丢段」的乌龙就是块号错位）。

## 六、文言与专名：为什么不能进音频（v1.3 教训，写进 SOP）

- 事实：v4 逐块 ASR 日志里 CER >25% 的三块全部落在《汉书》段——#5 28.21%（引文）、#8 25.64%（受大者不得取小）、#9 26.32%（公仪休）。
- 结论：本机 TTS 对文言、生僻专名最容易退化，同音串（「哨子含」≈「赵子涵」）还会系统性误读。
- 处理顺序（成本从低到高）：① 删字 / 换常用词（不新增生僻字，不用「攥」）；② 专名改称谓、原文转花字；③ 整句改白话。
- 花字要求：原文 / 六字 / 出处 / 人名必须**在屏幕上完整呈现**，信息零丢失；有起停时机的写进分镜表（例：块尾收句 → 0.8s 空拍 → 花字 2.5s）。

---

## 七、格式约定（给找素材 / 视频制作 / Chief）

- **段号与时间码**：md 里每段标 `S01` 等；时间码按 250 字/分估算，**实际以配音为准，段序不变**。
- **画面提示写法**：先给主体（汉代画像砖 / 菜市场实拍），再给动作（推近 / 翻页 / 局部描红）；**不写版权属性，不做版权判断**（2026-10-20 用户停用版权审核环节）。素材清单只按画面优先级排：1 公版图像 → 2 自制动画 → 3 实拍录屏 → 4 官方截屏，给找素材当检索方向，不承担审核职责。
- **字幕提示写法**：只写「要出现在屏幕上的字」，单行 ≤18 字，每段 ≤2 行；数字、年份、引文原文单独一行（走花字时不重复做字幕条）。
- **素材不足时**：找素材回来找我改画面提示，**口播不动**；若必须改口播，走第八节改稿流程，全链重跑。

---

## 八、改稿流程（口播一改，下游必须重出）

1. 任何人提修改 → 我改 md 与 txt **同步**，`scripts/稿本同步检查.py` 验 ALL SYNC，`scripts/脚本自检.py` 重跑，版本号 +1（文件名不变）。
2. 交付卡写清：改了哪几句、字数变化、**重出范围（时间码区间）**。
3. 口播一改，**该段及之后的配音、SRT 必须重出**；下游不许只改 txt 不回写 md，也不许只改 md 不重跑配音。
4. 结构性改动（换主轴、加案例）算新版本 v2.0，需管理员确认后再动。
5. 改稿记录按版本逐行写进 md 末尾（改动 / 字数 / 下游影响），不许只写在群消息里。

## 九、自检（随交付附，可复跑）

`python scripts/脚本自检.py <纯口播.txt> [目标分钟]`，输出：

| 指标 | 阈值（热档） |
|---|---|
| 有效字数与时长 | 目标时长 ±10%（250 字/分） |
| 平均句长 | ≤24 字 |
| 40 字以上长句 | 0 |
| 感叹号 | 0 |
| 设问间隔 | 每 100–150 字 1 处 |
| 数字 | 全部有口径，存疑标「有争议」 |

配套 `python scripts/稿本同步检查.py`：md 逐字稿口播行 ↔ 纯口播.txt 逐行比对，必须输出 `ALL SYNC`。
Chief 质检可直接跑这两个脚本，不用手数。
